# Database Design

Database name:

```txt
sneaker_shop
```

## Implemented collections

### `users`

Purpose:

- Store registered user accounts for authentication and profile display.

Main fields:

- `fullName`: string, required
- `email`: string, required, unique, lowercase
- `studentId`: string, required, unique
- `password`: string, required, hashed with bcrypt
- `role`: string, enum `student | admin`, default `student`
- `createdAt`: date, generated by Mongoose timestamps
- `updatedAt`: date, generated by Mongoose timestamps

Notes:

- Password is stored hashed and is excluded from query results by default.
- Authentication uses JWT generated from the user `_id`.

### `products`

Purpose:

- Store sneaker catalog data displayed across the storefront.

Main fields:

- `name`: string, required
- `slug`: string, unique
- `description`: string
- `category`: string, required
- `brand`: string
- `price`: number, required
- `salePrice`: number
- `images`: string array
- `stock`: number, default `0`
- `sold`: number, default `0`
- `views`: number, default `0`
- `sizes`: string array
- `colors`: string array
- `isPromotion`: boolean, default `false`
- `isNewProduct`: boolean, default `false`
- `isBestSeller`: boolean, default `false`
- `status`: string, enum `active | inactive`, default `active`
- `rating`: number, default `5`
- `numReviews`: number, default `0`
- `material`: string, default empty string
- `createdAt`: date, generated by Mongoose timestamps
- `updatedAt`: date, generated by Mongoose timestamps

Notes:

- A slug is generated automatically before save if one is not provided.
- Product detail lookup now supports either `_id` or `slug`.
- Product listing APIs only return active products.
